## 디자인 체계

`src/styles.css` 머리 주석에 규칙을 적어 두었습니다(11/14). 이전의 베이지 책상, 종이 그림자, 기울인 문서는 걷어냈습니다.

- **색:** 바탕은 흰색과 아주 옅은 회색, 글자는 먹색, 구분은 가는 선입니다. 빨강은 오류 선과 빨간 줄(그리고 로고 밑줄)에만 씁니다. 주 행동 버튼은 남색 한 가지입니다. 맞음은 초록, 사람 확인 전은 호박색입니다.
- **글꼴:** 화면 글자는 IBM Plex Sans KR입니다. 명조(Noto Serif KR)는 AI가 쓴 결과물 본문에만 써서 「검토할 서류」임을 드러냅니다. 손글씨(Nanum Pen Script)는 사람이 남긴 메모에만 씁니다.
- **크기:** 13 / 15 / 17 / 21 / 28 / 36px 여섯 단계입니다. 안내 문장은 15px 이상 먹색이고, 회색 작은 글자는 출처·각주에만 씁니다.
- **색만으로 구분하지 않습니다.** 찾음/놓침, 확실/의심 같은 글자 표시를 함께 둡니다.
- **모서리:** 기본은 직각입니다. 결재 서류와 원자료를 대조하는 도구라 서류·표·양식의 결을 따랐습니다. 둥근 것은 실제로 둥근 것만 둡니다(진행을 나타내는 점: 단계 레일 점·오류 경로 지도 점·순서 번호, 그리고 원형 도장).
- **움직임:** 보여 주는 화면(첫 화면, 결과)의 테두리 있는 상자만 스크롤 위치에 따라 가까운 가장자리에서 짧게 들어오고(0.42초), 되감으면 거꾸로 빠집니다(`src/ui/Slide.jsx`). 글과 일하는 화면(작업·짧은 연습·검수·팀장 모드)은 움직이지 않습니다. 뜻이 있는 움직임만 더했습니다. 오류가 번진 길의 선은 처음 틀린 단계에서 오른쪽으로 그어지고, 첫 화면 예시는 원자료 → S1 → S5 순서로 들어옵니다. transform·opacity만 쓰고, 움직임 줄이기 설정이면 `<html class="motion">`이 붙지 않아 모두 처음부터 제자리에 보입니다.

### 오늘의 연습(첫 화면, `#/`)

- **첫 화면에는 넷만 둡니다:** 질문형 제목(「AI가 끝낸 일, 어디서 틀렸을까요?」), 설명 한 문장, 「지금 해 보기」 버튼, 예시 그림. 노트북에서는 화면 높이에 맞춰 이것만 보이고, 나머지는 스크롤하면 한 덩어리에 한 생각씩 나옵니다(이렇게 진행됩니다 01·02·03 → 오늘의 연습 카드와 용어 한 줄 → 정답표 만드는 법 → 미션). 버튼은 사람 검수를 마친 첫 판으로 가고, 이미 푼 판이면 「결과 다시 보기」가 됩니다.
- **예시 그림:** 원자료 「추후 공지할 예정」 → S2 「없음 → 상시 신청 가능」(처음 틀림) → S5 「언제든 신청 가능!」(옮겨 적힘)을 단계 레일 위에 보여 줍니다. 풀 판의 문장이 아닌 예시임을 밝힙니다.
- **오늘의 연습 카드 4개(잡기 → 막기 → 증명)**
  - 잡기 · 판 하나: 판 하나 검수하기(사수 모드로).
  - 잡기 · 3문항: 짧은 연습 3문항(`#/drill`).
  - 막기 · 다시 시키기 약 30초(실측 31초): 놓친 오류 막아 보기. 결과 화면에서 하므로 카드는 판으로 갑니다.
  - 증명: 내 실력(`#/me`). 순위표는 두지 않는다고 적습니다.
- **곁 상자 두 개:** 「챗봇에게 틀린 곳을 찾아 달라고 하면 되지 않나요?」에 대한 답과, 정답표를 만드는 방법(오류를 심지 않음, 감사 → 코드 대조 → 사람 검수, 이의 제기)입니다.
- **미션 목록:** 미션마다 두 입구가 있습니다.
  - **검수해 보기(사수 모드):** 고정 판 목록을 장부 상태 표시와 함께 보여 줍니다. 이 브라우저에서 푼 판에는 「풀었음」을 붙입니다.
  - **직접 맡기기(팀장 모드):** 같은 미션을 맡긴 방식별로 돌린 기준 판의 최종본 A 평균을 「AI 감사 기준」으로 함께 적습니다.
  - 바로 풀 수 있는 판이 있는 미션을 먼저 보여 줍니다. 아직 검수할 판이 없는 미션은 「준비 중인 미션」 아래에 접어 둡니다.

### 사수 모드(`#/r/<판>`)

- **맨 위 띠:** 이 작업 기록을 어느 모델(회사)이 언제 실제로 수행했는지, 「결과물은 손대지 않았습니다」, 장부 상태(`정답표: 사람 검수 완료 · 장부 n판` 또는 `AI 감사(두 회사 이상) · 사람 확인 전`)를 적습니다.
- **문서 머리:** 문서번호와 미션 제목입니다. 작업 화면에는 결재란을 두지 않고(폭과 관계없이), 결과 화면에서만 결재란과 도장이 나옵니다.
- **할 일 카드:** 팀장 지시보다 위에 둡니다. ① 최종본(마지막 두 단계)을 원자료와 한 문장씩 대조 ② 틀린 문장을 누르면 빨간 줄, 확실한지 의심인지도 고름 ③ 맨 아래에서 승인 또는 반려. 「틀린 곳이 없을 수도 있습니다」, 「멈췄어야 할 곳」 설명, 원자료 문단이 화면에 보였는지는 결과 피드백에만 쓴다는 안내가 붙습니다.
- **단계 레일:** 작업 기록 위에 S5 → S1 순서로 단계 버튼이 붙어 있습니다(스크롤해도 위에 남음). 최종본 두 단계는 남색 테두리입니다. 내가 그 단계에 그은 빨간 줄이 점으로 찍히고(확실은 속 찬 점, 의심은 속 빈 점, 6개까지), 누르면 그 단계로 갑니다. 접힌 앞 단계는 펼치면서 갑니다.
- **읽는 순서:** 최종본(S5 → S4)을 먼저 펼쳐 둡니다. 앞 단계(S3 → S1)는 접어 두고, 이상한 곳이 있을 때 펼쳐 거슬러 올라갑니다. 접힌 단계 제목에는 칸 수와 그 단계에 그은 빨간 줄 수가 보입니다. 단계마다 「받은 것」(원자료, 팀장 지시, 앞 단계)과 접힌 「이 단계에 준 지시」가 있습니다.
- **누를 수 있는 문장:** 점선 밑줄이 있어 휴대폰에서도 보이고, 마우스를 올리거나 키보드 초점이 가면 밑줄이 빨개집니다. 최종본 첫 단계 제목 옆에 「문장을 눌러 빨간 줄」이라고 한 번 적습니다.
- **빨간 줄 창**
  - 칸을 그냥 누르면 문장 전체에, 끌어서 고르면 고른 구절에만 줄을 긋습니다. 끌기는 시작한 칸 안으로 자르고, 2자 이상만 받습니다.
  - 창 맨 위에는 **확실히 틀림(원자료와 대조해 확인했다) / 의심됨(확인이 더 필요하다)** 두 버튼(F3)과 「이 오류는 여기서 처음 생겼다」를 둡니다. 확실은 물결 빨간 줄, 의심은 끊긴 빨간 줄로 긋습니다.
  - 틀린 구절, 패턴(11종, 고르지 않아도 됨), 메모는 「구절·패턴·메모 더 적기(선택)」 아래 접어 둡니다. 구절을 끌어 골랐거나 이미 적은 것이 있으면 펼쳐서 엽니다. 메모는 칸 옆에 손글씨 여백 메모로 붙습니다.
  - 창이 열리면 초점은 입력 칸이 아니라 「확실히 틀림」 버튼에 갑니다. 휴대폰에서 키보드가 바로 올라와 화면을 가리지 않게 하려는 것입니다.
- **결재:** 「빨간 줄 n개를 그었습니다. 최종본을 이대로 내보내도 될까요?」를 묻습니다. 버튼에 뜻을 적었습니다(**승인: 이대로 내보냅니다 / 반려: 고쳐 오게 돌려보냅니다**). 반려하면 AI 동료에게 돌려보낼 사유(4자 이상)를 써야 합니다. 「결재하고 결과 보기」가 꺼져 있으면 그 아래에 이유(「승인 또는 반려를 먼저 고르세요」 / 「반려 사유를 4자 이상 적어 주세요」)를 적습니다. 원자료를 열어 본 횟수는 화면에 보이지 않지만 답안에는 그대로 기록합니다.
- **풀던 상태 저장:** 빨간 줄, 결재, 시작 시각, 원자료 열람 수, 근거 대조 기록을 이 브라우저에 임시로 둡니다(`redline:draft:<판>`). 새로고침해도 이어서 풀고, 제출하면 지웁니다.

### 근거 대조 기록(F2, `src/ui/trace.js`)

풀이 동안 「어느 원자료 문단이 언제 화면에 보였나」와 빨간 줄·결재 순서를 조용히 모읍니다. **점수에는 넣지 않고 결과 피드백에만 씁니다.**

- **이벤트 형식:** `[t, type, ref, ms?]`입니다. `t`는 풀이 시작부터 지난 밀리초이고, 벽시계 시각은 남기지 않습니다.
  - `open`·`close`(휴대폰 서랍), `tab`(원자료 문서 바꿈), `view`(문단이 보임, `ms`는 보인 시간), `tap`(문단 누름), `stage`(앞 단계 펼침), `mark`·`unmark`(빨간 줄), `decide`(승인·반려 고름).
  - 같은 문단이 이어서 보이면 `view` 하나로 합칩니다. 2,000개를 넘으면 오래된 `view`부터 버리고 버린 수를 셉니다.
- **「보였다」로 세는 규칙**
  - 원자료 패널을 한 번이라도 만진 뒤부터 셉니다(마우스 올림, 스크롤, 터치, 탭 누름, 문단 누름, 서랍 열기). 노트북에서는 원자료가 늘 펼쳐져 있어서, 만지기 전에 보인 것은 「본 것」으로 치지 않습니다.
  - 휴대폰 폭(820px 이하)에서는 서랍이 열려 있는 동안만 셉니다. 브라우저 탭이 가려져 있을 때도 세지 않습니다.
  - 문단이 60% 이상 보인 채 1.5초 이상 지나야 `view` 하나가 됩니다.
- **저장과 전송:** draft에 함께 저장하고(화면이 바뀔 때와 5초마다), 결재할 때 답안에 `trace`로 보냅니다. 이벤트 원본을 어떻게 두는지는 BE README 4절에 있습니다.

### 결과(사수 모드 제출 뒤): 놓친 것 따라가기

위에서부터 다음 순서입니다.

1. **장부가 바뀐 경우 알림.** 이의 제기 등으로 장부가 새 판이 되었으면, 이전 판 기준과 새 판 기준 A 찾음 수를 함께 적습니다.
2. **문서 머리와 도장.** 결재란에 내가 고른 승인·반려 도장이 찍힙니다.
3. **한 줄 판정.** 예: 「반려가 맞았습니다. 다만 꼭 잡아야 할 A등급 오류 5개 가운데 3개만 찾았습니다.」 점수 상자는 두 개입니다(A등급 오류 찾음 n/m, 결재 판정 맞음·틀림). 그 아래 작은 글씨로 헛짚음 수, 처음 생긴 곳 짚음, 기록용 합계 점수를 둡니다. 「점수 매기는 법」을 펼치면 배점(찾음 50 · 정확도 20 · 결재 20 · 처음 생긴 곳 10)과 A·B·C 구분을 설명합니다.
4. **오류가 번진 길(오류 경로 지도)**
   - 가로는 단계 S1 → S5, 줄 하나는 A등급 오류 하나입니다.
   - 속 찬 점은 처음 틀린 단계(`origin`), 속 빈 점은 옮겨 적힌 단계(`spread`)이고 선으로 잇습니다. 놓친 오류는 빨강, 찾은 오류는 초록이고 줄마다 「놓침」「찾음」 글자도 붙입니다.
   - 놓친 오류가 가장 먼저 시작된 단계에 「가장 먼저 멈췄어야 할 곳」 띠를 깝니다.
   - 줄을 누르면 그 오류 카드로 이동해 초점을 옮기고, 원자료 강조를 그 항목의 근거 문단으로 바꿉니다.
5. **이번 판에서 배운 것.**
   - 놓친 수와 유형, 가장 먼저 멈췄어야 할 단계와 거기서 시작된 오류 수, 결재가 맞았는지.
   - **근거 대조 줄:** 찾은 오류 가운데 근거 문단이 화면에 보인 뒤에 그은 수, 놓친 오류 가운데 근거 문단이 한 번도 화면에 나오지 않은 수(문단 번호와 함께). 원자료 패널을 만지지 않았으면 「근거 대조 기록이 없습니다」라고 적습니다.
   - **확신도 줄:** 확실·의심으로 그은 줄이 각각 몇 개 A등급 칸이었는지. 확실하다고 한 줄이 절반 넘게 빗나갔거나 의심한 줄이 모두 맞았으면 한 줄 조언을 붙입니다.
   - 다음에 맡길 때 넣을 지시 한 줄.
6. **놓친 A등급 오류 카드.** 패턴, 처음 생긴 곳 → 옮겨진 곳, 틀린 구절과 이유, 고친 문장, 「어디서 멈췄어야 했나」를 적습니다. 그 아래 칩이 붙습니다.
   - **근거 칩:** `근거 A-p3 · 한 번도 안 봄`처럼 근거 문단마다 내 대조 기록을 붙입니다(놓친 오류: 「봤지만 놓침」 / 「한 번도 안 봄」, 찾은 오류: 「보고 그음」 / 「앞 단계로 확인」 / 「보기 전에 그음」).
   - **출처 칩(F8):** 감사 몇 곳 가운데 몇 곳이 짚었는지(모두 놓쳤으면 「감사가 모두 놓침 · 사람 추가」), 근거 인용이 원자료에 그대로 있는지(코드 대조), 「사람 확정 · 장부 n판」, 사람 검수에서 바뀐 등급·처음 생긴 곳.
   - **집단 신호(F7):** 처음 푼 사람 수와, 5명 이상이면 찾은 비율.
   - 「처음 생긴 곳」 칸 이름이나 근거 칩을 누르면 아래 작업 기록 다시 보기의 그 칸으로 스크롤해 노랗게 반짝이고, 원자료에서 그 항목의 근거 문단을 강조합니다(휴대폰에서는 원자료 서랍이 열림).
   - 펼치면 확인 습관, 막는 지시, 근거 인용, 감사별 판정이 나옵니다.
7. **이 오류 막아 보기(F6).** 놓친 오류 카드마다 있습니다. 그 오류가 처음 생긴 단계의 받는 것과 지시를 보여 주고, 지시를 고쳐 쓰면(막는 지시를 끝에 넣는 버튼 있음) 같은 작업 모델이 같은 입력으로 그 단계만 다시 합니다. 판정은 「막음 / 남음 / 새 오류」이고(일부만 해결이면 「남음」, 감사가 실패해 알 수 없으면 「판정 못 함」), 감사 모델의 이유와 코드 판정(틀린 구절이 몇 % 남았나), 다시 한 결과를 보여 줍니다. 실제 모델을 부르고 기기당 하루 5번이며, 판정은 사람 확인 전이라 점수에 넣지 않습니다.
8. **그 밖의 항목.** 찾은 A등급 오류(접힘, 지도에서 누르면 열림), 장부에 없는 곳에 그은 줄 목록, B·C 참고(점수 없음, 접힘), 「판단이 갈리는 칸」(한 감사만 오류가 옮겨졌다고 본 칸, 찾음에도 헛짚음에도 넣지 않음)입니다.
9. **AI 1차 판정.** 결과를 먼저 보여 준 뒤 뒤에서 부릅니다. 내 빨간 줄에 원자료 근거가 있는지 보여 주고, `AI 1차 판정 · 사람 확인 전`으로 표시합니다. 점수에는 넣지 않습니다. 「새 오류 후보」는 만든 사람이 판정합니다. 판정이 실패하면 이 칸 없이 결과만 둡니다.
10. **작업 기록 다시 보기(S5 → S1).** 칸 색은 초록이 찾은 A, 빨강이 놓친 A, 노랑이 B·C, 하늘색이 판단이 갈리는 칸, 회색이 헛짚음입니다. 칸을 누르면 이의 제기 창이 뜹니다. 「장부에 없는 오류다」 또는 「오류가 아니다」를 고르고, 근거 문단과 이유(8자 이상)를 적어 보냅니다.
11. **「이 정답표에 대해」(접힘).** 장부 판, 감사 모델, 사람 검수에서 승인·수정·삭제·추가한 수를 적습니다.
12. **이어서 연습.** 짧은 연습 3문항으로 가는 버튼, 그리고 다음 행동 하나(아직 안 푼 판이 있으면 「다음 판 풀기」, 없으면 「습관 도감 보기」), 「오늘의 연습」·「내 실력」 링크입니다.

### 짧은 연습(F4, `#/drill`)

- 판의 문장 하나와 그 문장과 관련된 원자료 문단을 보여 주고 「이 문장은 원자료와 맞나요?」를 묻습니다. 버튼은 **맞다(원자료와 대조해 틀린 곳이 없다) / 틀렸다(원자료와 다르거나 원자료에 없다)**이고, 틀렸다를 고르면 유형을 골라도 됩니다(선택).
- 「확인」을 누르면 바로 정답표 기준 판정, 유형이 같은지, 그 칸에 걸친 장부 항목(틀린 구절, 이유, 고친 문장, 확인 습관)을 보여 줍니다. 정답표가 틀렸다고 생각하면 그 판 결과 화면에서 이의를 걸 수 있다고 안내합니다.
- 하루 3문항이고, 끝나면 「오늘 n/3 맞혔습니다」와 「3문항 더」, 「내 실력 보기」가 나옵니다.
- **결재까지 마친 판의 문장만 냅니다.** 판을 풀기 전에 정답이 새지 않게 하려는 것입니다. 아직 푼 판이 없으면 「판 하나 먼저 풀기」 버튼을 보여 줍니다. 틀린 문장은 사람 검수 장부에서, 맞는 문장은 만든 사람이 검수 화면에서 확정한 것만 씁니다.

### 팀장 모드(`#/lead/<미션>`)

1. **일 나누기와 지시**
   - 미션의 단계 정의를 기본 틀로 띄웁니다. S1은 원자료와 팀장 지시를, 뒤 단계는 바로 앞 단계를 받습니다. 지시 칸은 비어 있습니다.
   - 단계마다 종류(목록·표·문장·보고·짧은 줄·확인), 이름, 받을 것(원자료, 팀장 지시, 앞 단계들), 지시를 정합니다. 단계는 빼거나(최소 2개) 「여기 뒤에 확인 단계 넣기」로 더할 수 있습니다(최대 7개). 작업 모델 회사를 고르거나 무작위로 둡니다.
   - **지시 습관 점검표:** 쓰는 동안 ○·×가 바뀝니다(점수 아님). 뒤 단계에도 원자료를 넘김, 근거(출처) 표시를 요구함, 숫자·조건을 원문 표기대로 옮기라고 함, 오늘·게시일 기준을 알려 줌, 자료에 없으면 「확인 필요」로 두라고 함, 확인 단계를 넣음. 규칙은 서버(`lead.js`)의 습관 판정과 같습니다.
   - **「빈 단계를 기본 지시로 채우기」:** 비어 있는 단계만 고정 판을 만들 때 쓴 지시로 채웁니다. 그대로 두면 고정 판과 비슷한 오류가 날 수 있으니 고쳐 쓰라고 안내합니다.
2. **실행과 대조.** 단계마다 「시키기」를 누르면 AI 동료가 실제로 일합니다. 결과를 원자료와 대조해 「승인하고 다음」 또는 「반려」(사유 필요, 단계마다 한 번)를 고릅니다. 반려하면 사유를 붙여 다시 시킨 결과가 나옵니다.
3. **서명.** 「확인한 것」과 「확인하지 못한 것」을 적고 서명하면 감사로 넘어갑니다.
4. **독립 감사.** 작업 회사를 뺀 두 회사의 감사 모델이 하나씩 돌고, 끝난 감사의 항목 수와 걸린 초를 보여 줍니다. 한 곳이 끝나지 않으면 끝난 감사만 반영하고 그렇다고 알립니다.
5. **결과(점수 없음, `AI 감사 · 사람 확인 전`)**
   - 지표 상자 다섯 개: 최종본에 남은 A, 반려로 막은 A, A 중 사람이 확인한 오류와 같은 것, 원자료를 열어 본 횟수, 호출 수와 시간.
   - 「반려로 막음」은 글자 비교 기준(다시 한 결과에 틀린 구절의 글자쌍이 70% 이상 남지 않으면 막음)이라고 밝힙니다.
   - 같은 미션을 다른 방식(대충·기본·잘 맡김)으로 맡긴 기준 판 평균과 내 판을 한 표에 둡니다.
   - 내 지시에 있던 습관과 없던 습관을 ○·×로 보여 줍니다.
   - A등급 항목마다 운명(최종본에 남음, 앞 단계에만 있음, 반려로 막음, 반려했지만 비슷한 문장이 남음)을 붙이고, B·C는 접어 둡니다.
   - 작업 기록 칸을 눌러 이의를 제기할 수 있습니다.

### 습관 도감(`#/patterns`)

장부에서 실제로 나온 A등급 오류를 패턴별로 모읍니다(`/api/play` `patterns`에서 읽음). 패턴마다 사람 검수 수와 AI 감사 수를 따로 세고, 확인 습관과 작업 회사별·맡긴 방식별 빈도를 보여 줍니다. 예문은 사람 검수 판에서만 가져오고, **그 판을 결재한 기기에만** 열립니다(공개 수치 `/api/stats`에는 예문 없이 수만 있음). 잠긴 예문은 수와 그 판으로 가는 링크만 보입니다. 예문마다 틀린 구절, 처음 생긴 칸과 옮겨진 칸, 이유, 막는 지시, 「이 판 검수해 보기」 링크가 있습니다.

### 내 실력(F5, `#/me`)

이 브라우저의 무작위 기기 번호로 모은 기록입니다. 남과 견주는 순위는 두지 않고, 표본이 적으면 「아직 이릅니다」라고 그대로 적습니다.

- **오류 유형별로 찾은 정도:** 유형마다 막대와 「찾음 n/m」을 보여 주고, 약한 유형부터 늘어놓습니다. 막대는 (찾음 + 1) ÷ (만난 수 + 2)라서 처음엔 절반에서 시작합니다. 최신 사람 검수 장부로 다시 셉니다. 유형마다 3번 이상 만나야 「다음 추천」(가장 약한 유형, 습관 도감과 짧은 연습으로 가는 링크)을 냅니다.
- **짧은 연습:** 맞힘 수, 맞는 문장을 틀렸다고 한 수, 틀린 문장을 맞다고 한 수와, 어느 쪽으로 빗나가는지 한 줄.
- **판 검수 기록(사수 모드):** 판마다 A 찾음, 헛짚음, 결재 판정, 근거 보고 그은 수, 걸린 시간을 표로 보여 줍니다. 판이 3개 이상이면 앞쪽과 뒤쪽의 놓친 A 비율을 「판이 적어 우연일 수 있습니다」와 함께 보여 줍니다.
- **직접 맡기기(팀장 모드):** 판마다 최종본 A(AI 감사), 반려로 막은 A, 원자료 대조, 지시 습관 세 개(뒤 단계에 원자료, 근거 요구, 날짜 기준)를 보여 줍니다.

### 만든 방법과 검증(`#/about`)

- **실제 검사와 여기서 하는 것:** 실제 검사·기준(OECD·EC, HD현대, APTA, AISA)이 보는 것과 Redline에서 하는 것을 견준 표입니다.
- **왜 필요한가:** 원문을 확인한 공개 자료입니다. 학과 학생 설문은 결과가 들어오기 전이라 화면에 나오지 않습니다.
- **정답표 만드는 방법:** 작업 → 독립 감사 → 코드 대조 → 사람 검수 → 이의 제기 순서와 장부 상태 표시 규칙입니다.
- **기술 구성:** 직접 만든 것과 외부 기술, 한 번 부를 때 비용과 시간(실험 기준)입니다.
- **검증 수치**
  - 감사 모델이 심은 오류 20개를 찾았는지(BE `reports/g0/SUMMARY.md`에서 옮김).
  - 저절로 생긴 오류 81항목의 유형(AI 감사 기준, 사람 확인 전).
  - 사람 검수에서 장부가 바뀐 정도(G1: 항목 7(A 6) → 자동 나눔 +3, 자동 합침 −1, 사람이 삭제 −2, 사람이 추가 +1 → 8(A 5), 등급 바꿈 3). 표 아래에 이 계산식을 적어 둡니다.
  - 이의 제기 수와 사용 수.
  - 장부 변화, 이의, 사용 수는 API에서 읽습니다. 11/14 확인 기준 이의 접수 0건이고, 만든 사람을 뺀 사용은 검수 0판, 맡기기 0판입니다.
- **한계:** 감사마다 보는 폭이 다름, Google 감사가 G1의 A를 짚지 못함(판 하나라 일반화하지 않음), 사람 검수자가 한 명, 팀장 모드 장부는 사람 확인 전.

### 검수(`#/review`, 만든 사람 전용)

- 주소에 `?maker=1`을 붙여 들어오면 이 브라우저의 기록은 만든 사람 기록으로 따로 세어 집계에서 뺍니다(`?maker=0`이면 해제). 화면에는 아무 표시도 생기지 않습니다. 검수 화면은 메뉴에 두지 않고, 주소 `#/review`로 들어가거나 만든 사람 브라우저에서 로고를 1.5초 안에 다섯 번 누르면 열립니다.
- 검수 코드를 넣어야 열립니다. 코드는 이 브라우저에 두고, 요청 머리글 `x-review-code`로 보내 서버가 확인합니다.
- **대기열:** 장부 검수할 판과 이의·자동 판정 대기 건을 보여 줍니다. 판마다 「먼저 정답 없이 풀기」(사수 모드로 먼저 풂)와 「풀지 않고 열기」를 고를 수 있습니다.
- **판 검수:** 장부 항목을 작업 순서대로 하나씩 보여 주고, 「원자료와 견줘 틀렸나요?」 하나만 묻습니다. 답은 틀렸다(분명함) = A, 애매하다 = B, 사소하다 = C, 틀리지 않았다, 이 글은 맞고 뒤에서 틀렸다 가운데 고릅니다. 묶인 문장 나누기, 같은 오류 합치기, 오류가 옮겨진 곳 정하기는 코드가 합니다.
  - 만든 사람이 먼저 풀 때 그었지만 장부에 없는 빨간 줄은 「장부가 놓친 오류가 있나요?」 카드로 따로 띄웁니다.
  - 「감사가 놓친 오류 직접 찾기」 모드에서는 작업 기록 칸을 눌러 항목을 더합니다.
  - 남은 질문이 0개가 되어야 「정답표 확정」을 누를 수 있고, 누르면 장부 새 판이 됩니다.
- **이의 판정:** 사용자가 건 이의와 AI 1차 판정의 「장부에 없는 오류 후보」를 한곳에서 판정합니다. 받아들이면 장부 새 판이 생기고, 그 판을 푼 사람의 결과를 다시 계산합니다.
- **짧은 연습 문항 확정:** 사람 검수 장부가 있는 판에만 나옵니다. 틀린 문장 문항은 장부에서 자동으로 만들고(뺄 것만 고름), 「맞는 문장」 후보는 학생에게 「이 문장은 맞다」고 알려 주게 되므로 하나씩 「맞는 문장으로 냄 / 빼기」를 고르고 함께 보여 줄 원자료 문단(1~2개)을 정합니다. 판단이 갈리는 5개(S2.r4·S3.i3·S4.b2·S5.n3·S5.n1)는 미리 빼 두고, 감사 모델이 짚었다가 사람 검수에서 지운 흔적은 「감사 표시」로 보여 줍니다. 「이대로 확정」을 누르면 문항 세트 새 판이 되고, 그 판을 결재한 기기에서 짧은 연습이 열립니다.

## 휴대폰: 원자료 서랍

화면 폭이 820px 이하이면 원자료 칸을 왼쪽에 붙이지 않습니다. 작업 기록이 먼저 보이고, 오른쪽 아래에 떠 있는 「원자료 보기」 버튼을 누르면 원자료가 아래에서 올라오는 서랍(화면 높이의 72%까지)으로 열립니다. 사수 모드, 팀장 모드, 검수에서 같습니다.

- 서랍 머리의 「닫기」나 Esc로 닫습니다. 빨간 줄 창이 떠 있는 동안에는 버튼을 숨깁니다.
- 결과 화면에서는 떠 있는 버튼을 두지 않습니다. 카드의 「처음 생긴 곳」이나 근거 칩을 누르면 서랍이 저절로 열리고, 그 항목의 근거 문단이 강조됩니다.
- 사수 모드에서 서랍을 연 횟수는 원자료 대조 횟수로 셉니다. 근거 대조 기록은 서랍이 열려 있는 동안만 셉니다.
- 같은 폭에서 결과 화면은 「이번 판에서 배운 것」을 오류 경로 지도보다 먼저 보여 줍니다. 지도는 단계 이름을 숨기고 단계 번호만 남깁니다.
- 머리 메뉴는 한 줄로 두고 가로로 밉니다. 표도 가로로 밀어 봅니다(`overflow-x: auto`). 첫 화면 순서 안내와 연습 카드, 결재 버튼, 짧은 연습 버튼은 세로로 쌓습니다.

## 화면에서 정한 것

- **정답은 결재한 뒤에만 받습니다.** 판을 열 때(`GET /api/missions?run=`)는 원자료와 단계별 산출물만 받습니다. 장부는 결재를 낸 뒤 `/api/play` 응답으로 처음 받으므로, 개발자 도구로 미리 볼 수 없습니다. 짧은 연습도 결재한 판의 문장만 냅니다.
- **사실을 밝힙니다.**
  - 작업 기록마다 수행한 모델과 날짜, 「결과물은 손대지 않았습니다」를 적습니다.
  - 장부 상태 표시(`LedgerTag`)는 화면, README, 발표에서 같은 말을 씁니다.
  - 팀장 모드 결과, AI 1차 판정, 막아 보기 판정에는 「사람 확인 전」을 붙이고, 점수를 매기지 않습니다.
  - 첫 화면 예시 그림에는 실제 판의 정답이 아니라고 적습니다.
- **점수 밖 지표는 점수 밖에 둡니다.** 근거 대조, 확신도, 출처 칩, 집단 신호, 유형별 숙련도는 피드백으로만 보여 주고 점수 공식은 바꾸지 않습니다. 「화면에 보였다」는 「읽었다」가 아니기 때문입니다.
- **업무 검토처럼 읽히게 했습니다.** 문서번호, 단계 레일, 뜻이 적힌 결재 버튼, 결과의 결재란과 도장으로 퀴즈가 아니라 서류 검토처럼 보이게 했습니다. 꾸밈은 줄이고 빨강은 오류에만 남겼습니다(디자인 체계 절).
- **기록은 이름 없이 남깁니다.** 기기 번호는 브라우저가 만든 무작위 값이고 이름·연락처와 이어지지 않습니다. 이 브라우저에서 푼 판과 검수 코드는 브라우저 저장소에만 둡니다. 화면 바닥에 「어느 원자료 문단이 화면에 보였는지는 그 판의 결과 피드백에만 씁니다」라고 적습니다.
- **서비스 이름은 한 곳에 둡니다.** 이름과 부제(`Redline`, 「AI와 일하는 법 연습」)는 `src/brand.js`에 있습니다.

## 접근성

- **키보드로 모두 할 수 있습니다.**
  - 작업 기록의 칸(문장·표의 행)은 `role="button"`이라 Tab으로 옮겨 가고, Enter(문장은 Space도)로 빨간 줄 창을 엽니다.
  - 끌어서 구절을 고르기 어려우면 빨간 줄 창의 「틀린 구절」 칸에 직접 적으면 됩니다.
  - 단계 레일은 `<nav aria-label="단계 레일">` 안의 버튼이고, 읽어 주는 이름에 「S5 단톡방 공지, 빨간 줄 2개」처럼 단계와 줄 수를 담습니다(점은 `aria-hidden`).
- **떠 있는 창:** 빨간 줄 창과 이의 제기 창은 `role="dialog"`, `aria-modal`입니다. 열리면 첫 버튼(빨간 줄 창은 「확실히 틀림」)에 초점을 두고, Esc로 닫으며, 닫으면 원래 칸으로 초점을 돌려줍니다. 입력 칸에 바로 초점을 주지 않는 것은 휴대폰 키보드가 저절로 올라오지 않게 하려는 것입니다.
- **고르는 버튼:** 확실/의심, 승인/반려, 짧은 연습의 맞다/틀렸다는 `role="group"`(이름 붙음) 안의 버튼이고 고른 것을 `aria-pressed`로 알립니다. 버튼마다 뜻을 글로 적었습니다. 결재 버튼이 꺼진 이유와 짧은 연습 판정은 `aria-live="polite"`로 읽어 줍니다.
- **원자료:** 원자료 탭은 `role="tab"`과 `aria-selected`, 문서 제목을 담은 `aria-label`을 씁니다. 휴대폰 서랍 버튼은 `aria-expanded`·`aria-controls`를 씁니다.
- **오류 경로 지도:** 줄마다 버튼이고, 읽어 주는 이름에 「놓침 한정어·조건 탈락: S1에서 처음 틀려 S2·S4로 옮겨짐. 설명으로 가기」처럼 경로를 문장으로 담습니다. 그림(SVG)은 `aria-hidden`입니다. 색 말고도 「찾음」「놓침」 글자와 점 모양으로 구분합니다. 오류 카드는 초점을 받을 수 있어(`tabIndex=-1`) 지도에서 넘어가면 그 카드에 초점이 갑니다. 카드의 「처음 생긴 곳」 버튼은 「S1.e7 칸과 근거 원자료 보기」처럼 읽힙니다.
- **첫 화면 예시 그림:** `role="img"`와 그림 내용을 담은 `aria-label`을 둡니다.
- **빨간 줄:** 색과 함께 물결 밑줄로 긋고(의심은 끊긴 선), 메모는 글로 붙습니다. 결과에서 놓친 A 칸은 테두리, 판단이 갈리는 칸은 점선 테두리를 더합니다. 작업 기록 다시 보기의 나머지 칸(찾은 A, B·C, 헛짚음)은 배경색으로만 구분합니다. 같은 내용을 위의 카드와 목록에서 글로도 적습니다.
- **그 밖에**
  - 초점 표시는 3px 윤곽선(`:focus-visible`)입니다. 주 메뉴는 지금 화면에 `aria-current="page"`를 씁니다.
  - 한글은 낱말 단위로만 줄을 바꿉니다(`word-break: keep-all`). 긴 판 번호는 칸을 넘지 않게 끊습니다.
  - 동작 줄이기 설정(`prefers-reduced-motion`)을 켜면 도장 애니메이션, 서랍 미끄러짐, 지도 선 그리기, 칸 반짝임을 끕니다.
- **검수 화면 단축키:** 1·2·3·D는 답, J는 다음, K는 이전, Tab은 직접 찾기 모드 전환입니다. 화면에는 뜻이 적힌 버튼을 먼저 둡니다.

## 실행 방법

```bash
npm ci
npm test        # 단위 테스트 2개(빨간 줄 구절 처리)와 빌드
npm run dev     # http://localhost:5173, /api는 BE(localhost:3001)로 프록시
```

- BE를 먼저 띄웁니다(BE 저장소에서 `npm run dev`, 3001번). 키 없이도 미션·판 보기, 사수 모드 채점, 짧은 연습, 이의, 기록은 돌아갑니다. 팀장 모드, AI 1차 판정, 막아 보기에는 BE에 모델 API 키가 있어야 합니다(BE README 7절).
- **`VITE_API_BASE`:** BE 주소입니다. 비워 두면 같은 출처의 `/api`를 부르고, 개발 서버에서는 `vite.config.js`의 프록시가 `localhost:3001`로 넘깁니다. 배포할 때나 프록시 없이 띄울 때는 BE 주소를 넣습니다. 예: `VITE_API_BASE=http://localhost:3001 npm run dev`, 운영은 `https://woowangthon-44-be.vercel.app`. 빌드할 때 들어가는 값이라 바꾸면 다시 빌드해야 합니다.
- 만든 사람으로 들어가려면 주소에 `?maker=1`을 붙이고, 검수 화면에는 BE의 `REVIEW_CODE`와 같은 코드를 넣습니다.
