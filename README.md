# Redline · AI 결과물 검수 연습 — FE

**AI 활용 평가가 들어간 공채를 준비하는 대학생이, AI가 만든 결과물을 검수하는 연습을 하는 화면입니다.** AI 신입이 실제 공공 자료로 써 온 보고서에서 틀린 문장에 빨간 줄을 긋고 승인·반려 도장을 찍습니다.

- 서비스: https://woowangthon-44-fe.vercel.app (로그인 없음, 휴대폰 가능)
- 문제 정의, 근거, 파이프라인, 검증 수치, 한계: **[BE 저장소 README](https://github.com/woowangthon/WOOWANGTHON_TEAM_44_BE#readme)**
- 2026 AI 우왕톤 44팀 그라파이트

## 화면

| 주소 | 화면 | 하는 일 |
|---|---|---|
| `#/` | 결재함 | 오늘 올라온 보고서 10건(1분 맛보기, 문서, 표). 첫 화면에 대상과 「실제 검사가 보는 것 ↔ 여기서 하는 것」 대응표, 「챗봇에게 시키면 안 되나」에 대한 답 |
| `#/t/<id>` | 결재 | 업무 지시 → 1 검수 → 2 판정 → (반려하면 2차 결재) → 3 신입의 답 → 4 검토 평가서 |
| `#/new` | 새 보고서 받기 | 공공 자료를 고르거나 글을 붙여 넣으면 AI 신입이 그 자리에서 보고서를 씀. 서버의 실제 단계(작성 → 원자료 대조 → 오류 심기·검증 → 눈 가린 풀이)를 차례로 표시 |
| `#/new?focus=<유형>` | 약점 맞춤 | 고른 오류 유형 위주로 심은 새 보고서 |
| `#/exam` | 모의 검사 | 결재함 문서 3건을 12분 안에, 결재는 한 번씩 |
| `#/me` | 내 기록 | 이 브라우저의 기록, 오류 유형별 찾은 비율, 가장 많이 놓친 유형, 모두의 기록과 견주기 |
| `#/about` | 만든 방법과 근거 | 파이프라인, 2차 결재와 코칭 규칙, 근거, 한계 |

## 디자인에서 정한 것

- **결재 서류처럼.** 퀴즈처럼 읽히지 않도록 문서번호, 결재란(기안·검토), 첨부 원자료, 빨간 펜 줄과 여백 메모, 승인·반려 도장을 썼습니다. 그래서 문제, 정답, 채점 대신 보고서, 검수, 결재, 신입의 답이라는 말을 씁니다.
- **진행 단계를 늘 보입니다.** 「1 검수 → 2 판정 → 3 신입의 답 → 4 성적표」를 화면 위에 두고, 2차 결재면 「2차」 표시를 붙입니다.
- **정답은 채점 뒤에만 받습니다.** 화면은 원자료와 문장만 받아 그리고, 정답과 오류 수는 `/api/grade` 응답으로 처음 받습니다. 개발자 도구로 미리 볼 수 없습니다.
- **사실을 밝힙니다.** 보고서 위에 「연습용 보고서입니다. 일부 문장을 일부러 틀리게 바꿨을 수 있습니다.」를 늘 표시합니다. 과제에는 「사전 생성 · 자동 검증」(사람이 대조했으면 「· 사람 확인」) 또는 「방금 만든 과제 · 자동 검증만」 배지를 붙이고, 원문 링크를 답니다.
- **접근성**
  - 문장은 버튼이라 키보드로 표시할 수 있습니다(Tab, Enter, 숫자 키로 사유 선택).
  - 빨간 줄은 색과 함께 줄 긋기, 여백 메모, `aria-pressed`로도 구분합니다.
  - 좁은 화면에서는 원자료와 보고서를 탭으로 나눕니다.
  - 동작 줄이기 설정을 켜면 도장 애니메이션을 끕니다.
- **기록은 이름 없이 남깁니다.** 내 기록은 브라우저 저장소에만 둡니다. 서버에는 무작위 기기 번호와 결과만 보냅니다.

## 실행

```
npm ci
npm test        # 화면 규칙 단위 테스트(표시, 판정 확인, 공유 문구)와 빌드
npm run dev     # http://localhost:5173, /api는 BE(localhost:3001)로 프록시
```
배포할 때는 `VITE_API_BASE`에 BE 주소를 넣습니다. 서비스 이름은 `src/brand.js` 한 곳에 있습니다. `?maker=1`로 들어오면 만든 사람의 판으로 따로 세어 집계에서 뺍니다.
