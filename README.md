**지금 풀 수 있는 판은 1개입니다**(G1 `m4-base-anthropic-11121636-2`, 장부 3판). 나머지 판은 AI 감사만 거쳐 「사람 확인 전」으로 표시하고, 결재 버튼을 막아 채점하지 않습니다. 팀장 모드는 미션 세 개 모두에서 할 수 있고, 기기당 하루 2번입니다.

### 미션(첫 화면, `#/`)

- 첫 문단은 「내가 할 일」입니다. 그 아래 해 볼 순서(최종 공지 읽기 → 틀린 문장을 눌러 빨간 줄 → 승인 또는 반려 결재 → 결과)와 「지금 해 보기」 버튼을 둡니다. 버튼은 사람 검수를 마친 첫 판으로 갑니다.
- 곁 상자 두 개
  - 「챗봇에게 시키면 되지 않나요?」에 대한 답.
  - 정답표를 만드는 방법(오류를 심지 않음, 고정 판은 세 회사 감사, 팀장 모드는 작업 회사를 뺀 두 회사 감사, 사람 검수).
- 용어 한 줄: 사수 모드, 팀장 모드, 판(한 번 돌린 작업 기록), 장부(그 판의 오류 정답표).
- 미션마다 두 입구가 있습니다.
  - **검수해 보기(사수 모드):** 고정 판 목록을 장부 상태 표시와 함께 보여 줍니다. 이 브라우저에서 푼 판에는 「풀었음」을 붙입니다.
  - **맡겨 보기(팀장 모드):** 같은 미션을 맡긴 방식별로 돌린 기준 판의 최종본 A 평균을 「AI 감사 기준」으로 함께 적습니다.
- 바로 풀 수 있는 판이 있는 미션을 먼저 보여 줍니다. 아직 검수할 판이 없는 미션은 「준비 중인 미션」 아래에 접어 둡니다.

### 사수 모드(`#/r/<판>`)

- **맨 위 띠:** 이 작업 기록을 어느 모델(회사)이 언제 실제로 수행했는지, 「결과물은 손대지 않았습니다」, 장부 상태(`정답표: 사람 검수 완료 · 장부 n판` 또는 `AI 감사(두 회사 이상) · 사람 확인 전`)를 적습니다.
- **결재 서류 모양:** 문서번호와 결재란(기안 AI 동료, 검토 나)이 있고, 팀장 지시와 할 일이 이어집니다.
- **읽는 순서:** 최종본(마지막 두 단계, S5 → S4)을 먼저 펼쳐 둡니다. 앞 단계(S3 → S1)는 접어 두고, 이상한 곳이 있을 때 펼쳐 거슬러 올라갑니다. 접힌 단계 제목에는 칸 수와 그 단계에 그은 빨간 줄 수가 보입니다. 단계마다 「받은 것」(원자료, 팀장 지시, 앞 단계)과 「이 단계에 준 지시」가 있습니다.
- **빨간 줄 긋기**
  - 칸을 그냥 누르면 문장 전체에, 끌어서 고르면 고른 구절에만 줄을 긋습니다. 끌기는 시작한 칸 안으로 자르고, 2자 이상만 받습니다.
  - 편집 창에는 틀린 구절, 패턴(11종, 고르지 않아도 됨), 「이 오류는 여기서 처음 생겼다」, 메모가 있습니다. 메모는 칸 옆에 빨간 펜 여백 메모로 붙습니다.
- **결재:** 빨간 줄 수와 원자료를 열어 본 횟수를 보여 주고 「최종본을 이대로 내보내도 됩니까?」를 묻습니다. 승인·반려 도장 버튼이 있고, 반려하면 AI 동료에게 돌려보낼 사유(4자 이상)를 써야 합니다.
- **풀던 상태 저장:** 빨간 줄, 결재, 시작 시각, 원자료 열람 수를 이 브라우저에 임시로 둡니다. 새로고침해도 이어서 풀고, 제출하면 지웁니다.

### 결과(사수 모드 제출 뒤)

위에서부터 다음 순서입니다.

1. **장부가 바뀐 경우 알림.** 이의 제기 등으로 장부가 새 판이 되었으면, 이전 판 기준과 새 판 기준 결과를 함께 적습니다.
2. **한 줄 판정.** 예: 「반려가 맞았습니다. 다만 꼭 잡아야 할 A등급 오류 5개 가운데 3개만 찾았습니다.」 점수 상자는 두 개입니다(A등급 오류 찾음 n/m, 결재 판정 맞음·틀림). 그 아래 작은 글씨로 헛짚음 수, 처음 생긴 곳 짚음, 기록용 합계 점수를 둡니다. 「점수 매기는 법」을 펼치면 배점과 A·B·C 구분을 설명합니다.
3. **오류 경로 지도(「오류가 번진 길」)**
   - 가로는 단계 S1 → S5, 줄 하나는 A등급 오류 하나입니다.
   - 속 찬 점은 처음 틀린 단계(`origin`), 속 빈 점은 옮겨 적힌 단계(`spread`)입니다. 두 점을 선으로 잇습니다.
   - 놓친 오류는 빨강, 찾은 오류는 초록입니다. 줄마다 「놓침」「찾음」 글자도 붙입니다.
   - 놓친 오류가 가장 먼저 시작된 단계에 띠를 깔고 「가장 먼저 멈췄어야 할 곳」으로 표시합니다.
   - 줄을 누르면 그 오류 카드로 이동해 초점을 옮기고, 원자료 강조를 그 항목의 근거 문단으로 바꿉니다.
   - 장부 항목의 `origin`·`spread`만으로 그립니다(API를 바꾸지 않음).
4. **이번 판에서 배운 것.** 놓친 유형, 가장 먼저 멈췄어야 할 단계와 거기서 시작된 오류 수, 결재가 맞았는지, 다음에 맡길 때 넣을 지시 한 줄입니다.
5. **놓친 A등급 오류 카드.** 패턴, 처음 생긴 곳(누르면 원자료 근거 문단 강조), 옮겨진 곳, 틀린 구절과 이유, 고친 문장, 「어디서 멈췄어야 했나」를 적습니다. 펼치면 확인 습관, 막는 지시, 근거 인용, 감사별 판정이 나옵니다.
6. **그 밖의 항목.** 찾은 A등급 오류(접힘), 장부에 없는 곳에 그은 줄 목록, B·C 참고(점수 없음, 접힘), 「판단이 갈리는 칸」(한 감사만 오류가 옮겨졌다고 본 칸, 찾음에도 헛짚음에도 넣지 않음)입니다.
7. **AI 1차 판정.** 결과를 먼저 보여 준 뒤 뒤에서 한 번 부릅니다. 내 빨간 줄에 원자료 근거가 있는지 보여 주고, `AI 1차 판정 · 사람 확인 전`으로 표시합니다. 점수에는 넣지 않습니다. 「새 오류 후보」는 만든 사람이 판정합니다. 판정이 실패하면 이 칸 없이 결과만 둡니다.
8. **작업 기록 다시 보기(S5 → S1).** 칸 색은 초록이 찾은 A, 빨강이 놓친 A, 노랑이 B·C, 하늘색이 판단이 갈리는 칸, 회색이 헛짚음입니다. 칸을 누르면 이의 제기 창이 뜹니다. 「장부에 없는 오류다」 또는 「오류가 아니다」를 고르고, 근거 문단과 이유(8자 이상)를 적어 보냅니다.
9. **「이 정답표에 대해」.** 장부 판, 감사 모델, 사람 검수에서 승인·수정·삭제·추가한 수를 적습니다.
10. **다음 행동 하나.** 아직 안 푼 판이 있으면 「다음 판 풀기」, 없으면 「실패 패턴 보기」입니다.

### 팀장 모드(`#/lead/<미션>`)

1. **일 나누기와 지시**
   - 미션의 단계 정의를 기본 틀로 띄웁니다. S1은 원자료와 팀장 지시를, 뒤 단계는 바로 앞 단계를 받습니다.
   - 단계마다 종류(목록·표·문장·보고·짧은 줄·확인), 이름, 받을 것(원자료, 팀장 지시, 앞 단계들), 지시를 정합니다.
   - 단계는 빼거나(최소 2개) 「여기 뒤에 확인 단계 넣기」로 더할 수 있습니다(최대 7개).
   - 작업 모델 회사를 고르거나 무작위로 둡니다.
2. **실행과 대조.** 단계마다 「시키기」를 누르면 AI 동료가 실제로 일합니다. 결과를 원자료와 대조해 「승인하고 다음」 또는 「반려」(사유 필요, 단계마다 한 번)를 고릅니다. 반려하면 사유를 붙여 다시 시킨 결과가 나옵니다.
3. **서명.** 「확인한 것」과 「확인하지 못한 것」을 적고 서명하면 감사로 넘어갑니다.
4. **독립 감사.** 작업 회사를 뺀 두 회사의 감사 모델이 하나씩 돌고, 끝난 감사의 항목 수와 걸린 초를 보여 줍니다. 한 곳이 시간 안에 끝나지 않으면 끝난 감사만 반영하고 그렇다고 알립니다.
5. **결과(점수 없음, `AI 감사 · 사람 확인 전`)**
   - 지표 상자 다섯 개: 최종본에 남은 A, 반려로 막은 A, A 중 사람이 확인한 오류와 같은 것, 원자료를 열어 본 횟수, 호출 수와 시간.
   - 「반려로 막음」은 글자 비교 기준(다시 한 결과에 틀린 구절의 글자쌍이 70% 이상 남지 않으면 막음)이라고 밝힙니다.
   - 같은 미션을 다른 방식(대충·기본·잘 맡김)으로 맡긴 기준 판 평균과 내 판을 한 표에 둡니다.
   - 내 지시에 있던 습관과 없던 습관을 ○·×로 보여 줍니다.
   - A등급 항목마다 운명(최종본에 남음, 앞 단계에만 있음, 반려로 막음, 반려했지만 비슷한 문장이 남음)을 붙이고, B·C는 접어 둡니다.
   - 작업 기록 칸을 눌러 이의를 제기할 수 있습니다.

### 실패 패턴(`#/patterns`)

장부에서 실제로 나온 A등급 오류를 패턴별로 모읍니다(`/api/stats`에서 읽음). 패턴마다 사람 검수 수와 AI 감사 수를 따로 세고, 확인 습관과 작업 회사별·맡긴 방식별 빈도를 보여 줍니다. 예문은 사람 검수 판에서만 가져옵니다. 예문마다 틀린 구절, 처음 생긴 칸과 옮겨진 칸, 이유, 막는 지시, 「이 판 검수해 보기」 링크가 있습니다.

### 내 기록(`#/me`)

이 브라우저의 무작위 기기 번호로 모은 기록입니다.

- **사수 모드:** 판마다 A 찾음, 헛짚음, 결재 판정, 원자료 대조 횟수, 걸린 시간을 표로 보여 줍니다. 판이 3개 이상 쌓이기 전에는 추세를 말하지 않습니다. 3개 이상이면 앞쪽과 뒤쪽의 놓친 A 비율을 「판이 적어 우연일 수 있습니다」와 함께 보여 줍니다.
- **팀장 모드:** 판마다 최종본 A(AI 감사), 반려로 막은 A, 원자료 대조, 지시 습관 세 개(뒤 단계에 원자료, 근거 요구, 날짜 기준)를 보여 줍니다.

### 만든 방법과 검증(`#/about`)

- **실제 검사와 여기서 하는 것:** 실제 검사·기준(OECD·EC, HD현대, APTA, AISA)이 보는 것과 Redline에서 하는 것을 견준 표입니다.
- **왜 필요한가:** 원문을 확인한 공개 자료입니다. 학과 학생 설문은 결과가 들어오기 전이라 화면에 나오지 않습니다.
- **정답표 만드는 방법:** 작업 → 독립 감사 → 코드 대조 → 사람 검수 → 이의 제기 순서와 장부 상태 표시 규칙입니다.
- **기술 구성:** 직접 만든 것과 외부 기술, 한 번 부를 때 비용과 시간(실험 기준)입니다.
- **검증 수치**
  - 감사 모델이 심은 오류 20개를 찾았는지(BE `reports/g0/SUMMARY.md`에서 옮김).
  - 저절로 생긴 오류 81항목의 유형(AI 감사 기준, 사람 확인 전).
  - 사람 검수에서 장부가 바뀐 정도(G1: 항목 7(A 6) → 8(A 5), 삭제 2, 등급 바꿈 3, 사람이 추가 1).
  - 이의 제기 수와 사용 수.
  - 장부 변화, 이의, 사용 수는 API에서 읽습니다. 11/14 확인 기준 이의 접수 0건이고, 만든 사람을 뺀 사용은 검수 0판, 맡기기 0판입니다.
- **한계:** 감사마다 보는 폭이 다름, Google 감사가 G1의 A를 짚지 못함(판 하나라 일반화하지 않음), 사람 검수자가 한 명, 팀장 모드 장부는 사람 확인 전.

### 검수(`#/review`, 만든 사람 전용)

- 주소에 `?maker=1`을 붙여 들어오면 메뉴에 「검수」와 「만든 사람 모드」 표시가 생깁니다. 이 브라우저의 기록은 만든 사람 기록으로 따로 세어 집계에서 뺍니다(`?maker=0`이면 해제).
- 검수 코드를 넣어야 열립니다. 코드는 이 브라우저에 두고, 요청 머리글 `x-review-code`로 보내 서버가 확인합니다.
- **대기열:** 장부 검수할 판과 이의·자동 판정 대기 건을 보여 줍니다. 판마다 「먼저 정답 없이 풀기」(사수 모드로 먼저 풂)와 「풀지 않고 열기」를 고를 수 있습니다.
- **판 검수:** 장부 항목을 작업 순서대로 하나씩 보여 주고, 「원자료와 견줘 틀렸나요?」 하나만 묻습니다. 답은 틀렸다(분명함) = A, 애매하다 = B, 사소하다 = C, 틀리지 않았다, 이 글은 맞고 뒤에서 틀렸다 가운데 고릅니다. 묶인 문장 나누기, 같은 오류 합치기, 오류가 옮겨진 곳 정하기는 코드가 합니다.
  - 만든 사람이 먼저 풀 때 그었지만 장부에 없는 빨간 줄은 「장부가 놓친 오류가 있나요?」 카드로 따로 띄웁니다.
  - 「감사가 놓친 오류 직접 찾기」 모드에서는 작업 기록 칸을 눌러 항목을 더합니다.
  - 남은 질문이 0개가 되어야 「정답표 확정」을 누를 수 있고, 누르면 장부 새 판이 됩니다.
- **이의 판정:** 사용자가 건 이의와 AI 1차 판정의 「장부에 없는 오류 후보」를 한곳에서 판정합니다. 받아들이면 장부 새 판이 생기고, 그 판을 푼 사람의 결과를 다시 계산합니다.

## 휴대폰: 원자료 서랍

화면 폭이 820px 이하이면 원자료 칸을 왼쪽에 붙이지 않습니다. 작업 기록이 먼저 보이고, 오른쪽 아래에 떠 있는 「원자료 보기」 버튼을 누르면 원자료가 아래에서 올라오는 서랍(화면 높이의 72%까지)으로 열립니다. 이 동작은 사수 모드, 결과, 팀장 모드, 검수에서 같습니다.

- 서랍 머리의 「닫기」나 Esc로 닫습니다. 빨간 줄 편집 창이 떠 있는 동안에는 버튼을 숨깁니다.
- 결과 화면에서 카드의 「처음 생긴 곳」을 누르면 서랍이 저절로 열리고, 그 항목의 근거 문단이 강조됩니다.
- 서랍을 연 횟수는 원자료 대조 횟수로 셉니다.
- 같은 폭에서 결과 화면은 「이번 판에서 배운 것」을 오류 경로 지도보다 먼저 보여 줍니다. 지도는 단계 이름을 숨기고 단계 번호만 남깁니다.
- 표는 가로로 밀어 봅니다(`overflow-x: auto`). 첫 화면 순서 안내는 세로로 쌓습니다.

브라우저 375px 폭에서만 확인했고, 휴대폰 실기기에서는 확인하지 않았습니다(BE README 「한계」와 같음).

## 화면에서 정한 것

- **정답은 결재한 뒤에만 받습니다.** 판을 열 때(`GET /api/missions?run=`)는 원자료와 단계별 산출물만 받습니다. 장부는 결재를 낸 뒤 `/api/play` 응답으로 처음 받으므로, 개발자 도구로 미리 볼 수 없습니다.
- **사실을 밝힙니다.**
  - 작업 기록마다 수행한 모델과 날짜, 「결과물은 손대지 않았습니다」를 적습니다.
  - 장부 상태 표시(`LedgerTag`)는 화면, README, 발표에서 같은 말을 씁니다.
  - 팀장 모드 결과와 AI 1차 판정에는 늘 「사람 확인 전」을 붙이고, 점수를 매기지 않습니다.
- **결재 서류처럼 보이게 했습니다.** 문서번호, 결재란, 빨간 펜 줄과 여백 메모, 승인·반려 도장으로 퀴즈가 아니라 업무 검토처럼 읽히게 했습니다.
- **기록은 이름 없이 남깁니다.** 기기 번호는 브라우저가 만든 무작위 값이고 이름·연락처와 이어지지 않습니다. 이 브라우저에서 푼 판과 검수 코드는 브라우저 저장소에만 둡니다.
- **서비스 이름은 한 곳에 둡니다.** 이름과 부제(`Redline`, 「AI와 일하는 법 연습」)는 `src/brand.js`에 있습니다.

## 접근성

- **키보드로 모두 할 수 있습니다.**
  - 작업 기록의 칸(문장·표의 행)은 `role="button"`이라 Tab으로 옮겨 가고, Enter(문장은 Space도)로 빨간 줄 편집 창을 엽니다.
  - 끌어서 구절을 고르기 어려우면 편집 창의 「틀린 구절」 칸에 직접 적으면 됩니다.
- **떠 있는 창:** 빨간 줄 편집 창과 이의 제기 창은 `role="dialog"`, `aria-modal`입니다. 열리면 첫 입력 칸에 초점을 두고, Esc로 닫으며, 닫으면 원래 칸으로 초점을 돌려줍니다.
- **원자료:** 원자료 탭은 `role="tab"`과 `aria-selected`, 문서 제목을 담은 `aria-label`을 씁니다. 휴대폰 서랍 버튼은 `aria-expanded`·`aria-controls`를 씁니다.
- **오류 경로 지도:** 줄마다 버튼이고, 읽어 주는 이름에 「놓침 한정어·조건 탈락: S1에서 처음 틀려 S2·S4로 옮겨짐. 설명으로 가기」처럼 경로를 문장으로 담습니다. 그림(SVG)은 `aria-hidden`입니다. 색 말고도 「찾음」「놓침」 글자와 점 모양(속 찬 점, 속 빈 점)으로 구분합니다. 오류 카드는 초점을 받을 수 있어 지도에서 넘어가면 그 카드에 초점이 갑니다.
- **빨간 줄:** 색과 함께 물결 밑줄로 긋고, 메모는 글로 붙습니다. 결과에서 놓친 A 칸은 테두리, 판단이 갈리는 칸은 점선 테두리를 더합니다. 작업 기록 다시 보기의 나머지 칸(찾은 A, B·C, 헛짚음)은 배경색으로만 구분합니다. 같은 내용을 위의 카드와 목록에서 글로도 적습니다.
- **그 밖에**
  - 초점 표시는 3px 윤곽선(`:focus-visible`)입니다. 주 메뉴는 지금 화면에 `aria-current`를 씁니다.
  - 한글은 낱말 단위로만 줄을 바꿉니다(`word-break: keep-all`). 긴 판 번호는 칸을 넘지 않게 끊습니다.
  - 동작 줄이기 설정(`prefers-reduced-motion`)을 켜면 도장 애니메이션, 서랍 미끄러짐, 지도 선 그리기를 끕니다.
- **검수 화면 단축키:** 1·2·3·D는 답, J는 다음, K는 이전, Tab은 직접 찾기 모드 전환입니다. 화면에는 뜻이 적힌 버튼을 먼저 둡니다.

## 실행 방법

```bash
npm ci
npm test        # 단위 테스트 2개(빨간 줄 구절 처리)와 빌드
npm run dev     # http://localhost:5173, /api는 BE(localhost:3001)로 프록시
```

- BE를 먼저 띄웁니다(BE 저장소에서 `npm run dev`, 3001번). 키 없이도 미션·판 보기, 사수 모드 채점, 이의, 기록은 돌아갑니다. 팀장 모드와 AI 1차 판정에는 BE에 모델 API 키가 있어야 합니다(BE README 7절).
- **`VITE_API_BASE`:** BE 주소입니다. 비워 두면 같은 출처의 `/api`를 부르고, 개발 서버에서는 `vite.config.js`의 프록시가 `localhost:3001`로 넘깁니다. 배포할 때나 프록시 없이 띄울 때는 BE 주소를 넣습니다. 예: `VITE_API_BASE=http://localhost:3001 npm run dev`, 운영은 `https://woowangthon-44-be.vercel.app`. 빌드할 때 들어가는 값이라 바꾸면 다시 빌드해야 합니다.
- 만든 사람으로 들어가려면 주소에 `?maker=1`을 붙이고, 검수 화면에는 BE의 `REVIEW_CODE`와 같은 코드를 넣습니다.
