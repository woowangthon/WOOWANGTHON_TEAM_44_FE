# Redline · AI 작업 기록 검수 연습 — FE

**Redline은 AI가 다섯 단계로 끝낸 작업 기록을 원자료와 대조해 틀린 곳을 찾고, 놓친 오류가 어디서 생겼는지 돌려받는 검수 연습 서비스입니다.**
AI 동료(실제 모델)가 공공 보도자료로 일을 처리하고, 오류는 일부러 심지 않습니다. 사용자는 빨간 줄을 긋고 결재하거나(사수 모드), 직접 일을 나누어 맡겨 봅니다(팀장 모드).
이 저장소는 그 화면입니다. 문제 정의, 근거, 파이프라인, 검증 수치, 한계는 **[BE 저장소 README](https://github.com/woowangthon/WOOWANGTHON_TEAM_44_BE#readme)**에 있습니다.

## 화면에서 정한 것

**정답과 공개**

- **결재 전에는 브라우저 응답에 정답이 없습니다(장부 파일은 공개 저장소에 있음).** 판을 열 때(`GET /api/missions?run=`)는 원자료와 단계별 산출물만 받고, 장부는 결재를 낸 뒤 `/api/play` 응답으로 처음 받습니다. 짧은 연습도 결재한 판의 문장만 냅니다. 판을 풀기 전에 그 판의 정답이 새지 않게 하려는 것입니다.
- **습관 도감 예문은 그 판을 결재한 기기에만 열립니다.** 공개 수치(`/api/stats`)에는 예문 없이 수만 있고, 잠긴 예문은 수와 그 판으로 가는 링크만 보입니다.
- **사실을 밝힙니다.** 작업 기록마다 수행한 모델과 날짜, 「결과물은 손대지 않았습니다」, 장부 상태(사람 검수 완료 / AI 감사 · 사람 확인 전)를 적습니다. 팀장 모드 결과, AI 1차 판정, 막아 보기 판정에는 「사람 확인 전」을 붙이고 점수를 매기지 않습니다. 첫 화면 예시 그림에는 실제 판의 정답이 아니라고 적습니다.
- **점수 밖 지표는 점수 밖에 둡니다.** 근거 대조, 확신도, 출처 칩, 집단 신호, 유형별 숙련도는 피드백으로만 보여 줍니다. 「화면에 보였다」는 「읽었다」가 아니기 때문입니다.

**사수 모드**

- **읽는 순서:** 최종본(S5 → S4)을 먼저 펼치고, 앞 단계(S3 → S1)는 접어 둡니다. 이상한 곳이 있을 때 펼쳐 거슬러 올라갑니다. 작업 기록 위 단계 레일에 그 단계에 그은 빨간 줄이 점으로 찍히고, 누르면 그 단계로 갑니다.
- **빨간 줄:** 칸을 누르면 문장 전체에, 끌어서 고르면 고른 구절에만 긋습니다. 창 맨 위에는 **확실히 틀림(원자료와 대조해 확인했다) / 의심됨(확인이 더 필요하다)** 두 버튼을 둡니다. 틀린 구절·패턴·메모는 선택이라 접어 둡니다.
- **결재:** 버튼에 뜻을 적었습니다(**승인: 이대로 내보냅니다 / 반려: 고쳐 오게 돌려보냅니다**). 반려하려면 사유를 써야 하고, 버튼이 꺼져 있으면 그 이유를 아래에 적습니다.
- **풀던 상태 저장:** 빨간 줄, 결재, 근거 대조 기록을 이 브라우저에 임시로 둬서 새로고침해도 이어서 풉니다. 제출하면 지웁니다.

**근거 대조 기록(`src/ui/trace.js`)**

- 풀이 동안 어느 원자료 문단이 언제 화면에 보였는지와 빨간 줄·결재 순서를 모읍니다. 벽시계 시각은 남기지 않습니다.
- 원자료 패널을 한 번이라도 만진 뒤부터, 문단이 60% 이상 보인 채 1.5초 이상 지나야 「보였다」로 셉니다. 노트북에서는 원자료가 늘 펼쳐져 있어서입니다. 휴대폰 폭에서는 서랍이 열려 있는 동안만 셉니다.

**결과**

- 점수 상자는 두 개(A등급 오류 찾음 n/m, 결재 판정)이고, 헛짚음과 기록용 합계 점수는 작게 둡니다.
- **오류 경로 지도:** 가로는 S1 → S5, 줄 하나는 A등급 오류 하나입니다. 속 찬 점은 처음 틀린 단계, 속 빈 점은 옮겨 적힌 단계입니다. 놓친 오류가 가장 먼저 시작된 단계에 「가장 먼저 멈췄어야 할 곳」 띠를 깝니다.
- **놓친 오류 카드:** 처음 생긴 곳 → 옮겨진 곳, 틀린 구절과 이유, 고친 문장과 함께 근거 칩(그 근거 문단을 봤는지), 출처 칩(감사 몇 곳이 짚었나, 사람이 확정한 장부 버전), 집단 신호(5명 이상일 때 찾은 비율)를 붙입니다.
- **이 오류 막아 보기:** 그 오류가 처음 생긴 단계의 입력과 지시를 보여 주고, 지시를 고쳐 쓰면 같은 작업 모델이 그 단계만 다시 합니다. 판정은 「막음 / 남음 / 새 오류」이고 점수에 넣지 않습니다(기기당 하루 5번).
- **다른 사람들은 어땠나:** 점수 아래에 이 판을 처음 푼 사람들(만든 사람 제외, 같은 브라우저는 첫 풀이만)이 A를 몇 개 찾았는지 가로 막대 분포로 보이고, 내 줄만 굵게 표시합니다. 결재를 맞힌 사람 수와 만든 사람이 정답표를 보기 전 처음 풀었을 때 찾은 수도 적습니다. 순위는 두지 않고, 5명 미만이면 「우연이 크다」고 적습니다. 외부 시험에서 「내가 이렇게 많이 놓쳤나」라는 말이 나와, 남들도 많이 놓친다는 것을 숫자로 보이려는 것입니다.
- **이 판 다시 풀기:** 앞 결과를 따로 두고 빨간 줄을 비워 다시 엽니다. 푸는 동안 「다시 풀기 중」 안내와 「앞 결과로 돌아가기」가 있고, 다시 푼 기록은 분포·유형별 통계에 넣지 않습니다(내 실력 표에 「다시 풂」).

**짧은 연습**

- 버튼은 **맞다(원자료와 대조해 틀린 곳이 없다) / 틀렸다(원자료와 다르거나 원자료에 없다)**입니다. 「확인」을 누르면 바로 판정과 그 칸에 걸친 장부 항목(틀린 구절, 이유, 확인 습관)을 보여 줍니다.
- 틀린 문장은 사람 검수 장부에서, 맞는 문장은 만든 사람이 확정한 것만 씁니다.
- 문항이 있는 판을 아직 결재하지 않았으면, 어느 판을 풀면 열리는지와 그 판으로 가는 버튼, 「모의 문제집부터」를 보여 줍니다.
- **모의 문제집**은 같은 화면을 씁니다. 판 없이 풀 수 있게 판 목록에 없는 두 판에서 고른 7문항이고, 끝에 내 점수와 끝까지 푼 다른 사람들의 분포, 놓친 쪽(맞는 문장을 틀렸다고 함 / 틀린 문장을 맞다고 함)에 맞춘 요령을 보여 줍니다.

**팀장 모드**

- 단계마다 종류, 이름, 받을 것, 지시를 정합니다. 단계는 2~7개입니다.
- **지시 습관 점검표:** 쓰는 동안 ○·×가 바뀝니다(점수 아님). 뒤 단계에도 원자료를 넘김, 근거 표시를 요구함, 숫자·조건을 원문 표기대로, 날짜 기준을 알려 줌, 자료에 없으면 「확인 필요」, 확인 단계를 넣음. 규칙은 서버(`lead.js`)와 같습니다.
- 결과에는 같은 미션을 대충·기본·잘 맡긴 기준 판의 평균과 내 판을 한 표에 둡니다. 「반려로 막음」은 글자 비교 기준이라고 밝힙니다.

**내 실력**

- 오류 유형마다 「찾음 n/m」과 막대를 보여 주고, 약한 유형부터 늘어놓습니다. 막대는 (찾음 + 1) ÷ (만난 수 + 2)라서 처음엔 절반에서 시작합니다.
- 유형마다 3번 이상 만나기 전에는 다음에 연습할 유형을 추천하지 않습니다. 순위표는 두지 않고, 맨 위 「나와 다른 사람들」 표에서 A등급 오류를 찾은 비율과 결재를 맞힌 비율을 다른 사람들(만든 사람 제외, 첫 풀이만)과 나란히 둡니다. 유형마다 「다른 사람 n%」를 붙이고, 놓친 유형의 확인 습관을 「요령」으로 최대 3개 보여 줍니다.

**휴대폰(820px 이하)**

- 원자료는 화면 맨 아래 전체 폭 「원자료 보기」 띠로 여는 아래 서랍(화면 높이의 55%까지)입니다. 떠 있는 버튼이 글을 가리지 않게 띠로 두었고, 서랍이 열리면 단계 레일 고정을 풀어 작업 기록을 넓게 봅니다(외부 시험자의 「휴대폰이 불편하다」는 후기로 고침). 결과 화면에서는 카드의 「처음 생긴 곳」이나 근거 칩을 누르면 서랍이 저절로 열리고 근거 문단이 강조됩니다.
- 결과 화면은 「이번 판에서 배운 것」을 지도보다 먼저 보여 줍니다. 메뉴는 3칸×2줄로 모두 보이고, 표는 가로로 밀어 봅니다.

**기록은 이름 없이 남깁니다.** 기기 번호는 브라우저가 만든 무작위 값이고 이름·연락처와 이어지지 않습니다.

## 디자인 원칙

- **업무 서류처럼 보이게 했습니다.** 결재 서류와 원자료를 대조하는 연습이라 문서번호, 단계 레일, 뜻이 적힌 결재 버튼, 결과의 결재란과 도장을 두어 퀴즈가 아니라 서류 검토처럼 읽히게 했습니다. 모서리는 직각을 기본으로 합니다.
- **빨강은 오류에만 씁니다.** 바탕은 흰색과 옅은 회색, 글자는 먹색이고, 빨강은 오류 선과 빨간 줄에만 씁니다. 주 행동 버튼은 남색 한 가지입니다.
- **글꼴로 역할을 나눕니다.** 화면 글자는 IBM Plex Sans KR, AI가 쓴 결과물 본문은 명조(Noto Serif KR), 사람이 남긴 메모는 손글씨(Nanum Pen Script)입니다.
- **색만으로 구분하지 않습니다.** 찾음/놓침, 확실/의심 같은 글자 표시와 점·선 모양을 함께 둡니다(접근성).

## 접근성

- **키보드로 모두 할 수 있습니다.** 작업 기록의 칸(문장·표의 행)은 `role="button"`이라 Tab으로 옮겨 가고 Enter로 빨간 줄 창을 엽니다. 끌어서 구절을 고르기 어려우면 「틀린 구절」 칸에 직접 적으면 됩니다.
- **떠 있는 창:** 빨간 줄 창과 이의 제기 창은 `role="dialog"`, `aria-modal`입니다. 열리면 첫 버튼에 초점을 두고, Esc로 닫으며, 닫으면 원래 칸으로 초점을 돌려줍니다. 입력 칸에 바로 초점을 주지 않아 휴대폰 키보드가 저절로 올라오지 않습니다.
- **고르는 버튼:** 확실/의심, 승인/반려, 맞다/틀렸다는 이름 붙은 `role="group"` 안의 버튼이고 고른 것을 `aria-pressed`로 알립니다. 결재 버튼이 꺼진 이유와 짧은 연습 판정은 `aria-live="polite"`로 읽어 줍니다.
- **단계 레일과 오류 경로 지도:** 읽어 주는 이름에 「S5 단톡방 공지, 빨간 줄 2개」, 「놓침 한정어·조건 탈락: S1에서 처음 틀려 S2·S4로 옮겨짐」처럼 내용을 문장으로 담고, 그림(SVG)과 점은 `aria-hidden`입니다.
- **원자료:** 탭은 `role="tab"`과 `aria-selected`, 휴대폰 서랍 버튼은 `aria-expanded`·`aria-controls`를 씁니다.
- **그 밖에:** 초점 표시는 3px 윤곽선(`:focus-visible`), 한글은 낱말 단위 줄바꿈(`word-break: keep-all`)입니다. 동작 줄이기 설정(`prefers-reduced-motion`)을 켜면 움직임을 끕니다.

## 실행 방법

```bash
npm ci
npm test        # 단위 테스트 2개(빨간 줄 구절 처리)와 빌드
npm run dev     # http://localhost:5173, /api는 BE(localhost:3001)로 프록시
```

- BE를 먼저 띄웁니다(BE 저장소에서 `npm run dev`, 3001번). 키 없이도 미션·판 보기, 사수 모드 채점, 짧은 연습, 이의, 기록은 돌아갑니다. 팀장 모드, AI 1차 판정, 막아 보기에는 BE에 모델 API 키가 있어야 합니다(BE README 7절).
- **`VITE_API_BASE`:** BE 주소입니다. 비워 두면 같은 출처의 `/api`를 부르고, 개발 서버에서는 `vite.config.js`의 프록시가 `localhost:3001`로 넘깁니다. 운영 값은 `https://woowangthon-44-be.vercel.app`입니다. 빌드할 때 들어가는 값이라 바꾸면 다시 빌드해야 합니다.
- 브라우저의 375px·1280px 폭으로 확인했습니다. 휴대폰 실기기는 외부 시험자 1명의 후기뿐이고, 그 뒤 고친 화면은 실기기에서 다시 보지 않았습니다.
